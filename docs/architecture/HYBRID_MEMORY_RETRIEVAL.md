# Hybrid Memory Retrieval and Optional Embeddings

**Implementation branch:** `oracle/phase-02-hybrid-retrieval`  
**Parent memory work:** PR #8 — Episodic and validated procedural memory.

## Design

The memory path combines two retrieval modes:

1. Existing deterministic lexical retrieval from `memory.py` and `memory_layers.py`.
2. Optional vector retrieval from a configured embeddings endpoint.

The two ranked result sets are combined with Reciprocal Rank Fusion (RRF). The lexical path remains the fallback and does not depend on embeddings.

## Embedding provider contract

`memory_embeddings.EmbeddingClientProtocol` is the provider-independent interface:

- `model_name`
- `embed(texts) -> vectors`

The included `OpenAICompatibleEmbeddingClient` supports endpoints exposing `POST /embeddings`. This includes compatible local endpoints when they implement that contract. The default configured provider is Ollama on loopback; hosted OpenAI-compatible endpoints require explicit configuration.

No embedding provider is called unless the feature is explicitly enabled and a model is configured.

### Environment configuration

| Variable | Purpose | Default |
|---|---|---|
| `ORACLE_MEMORY_EMBEDDINGS_ENABLED` | Enable vector retrieval/indexing integration | `0` |
| `ORACLE_EMBEDDING_PROVIDER` | `ollama` or `openai_compatible` | `ollama` |
| `ORACLE_EMBEDDING_MODEL` | Explicit embedding model name | Empty (disabled) |
| `OLLAMA_EMBEDDING_MODEL` | Fallback model name for the Ollama profile | Empty |
| `ORACLE_EMBEDDING_BASE_URL` | Embeddings API base URL | Provider default |
| `ORACLE_EMBEDDING_API_KEY` | Explicit embedding API key, where required | Empty |
| `ORACLE_MEMORY_EMBEDDINGS_AUTOINDEX` | Rebuild missing/changed index during retrieval | `0` |

For the local profile, the default base URL is `http://127.0.0.1:11434/v1`. The configured embedding model must support the compatible embeddings endpoint; installing or starting Ollama is not performed by this code.

A hosted endpoint is used only when `ORACLE_EMBEDDING_PROVIDER=openai_compatible` is explicitly configured. The excerpts sent to that service are the memory texts selected for indexing and the current search query. Review local/cloud privacy requirements before enabling a hosted endpoint.

## SQLite vector cache

The new `memory_embeddings` table stores:

- Scope.
- Memory category and record ID.
- Embedding model.
- SHA-256 content hash.
- Vector JSON and dimensions.
- Created/updated timestamps.

It does not store a second copy of the raw memory text. Vectors are isolated by scope and model name.

Supported source categories:

- Existing semantic memory: fact, preference, goal.
- Episodic event records.
- Validated procedures only.

Candidate and retired procedures are not indexed for normal retrieval.

Indexing is bounded by a maximum record count and batch size. Repeated indexing skips records whose content hash has not changed. Changed records are re-embedded. Indexing does not delete source memories or vector rows.

## Stale index behavior

Each vector row is checked against the current source record and its content hash at retrieval time. Missing or changed records are ignored. They are not silently treated as current semantic matches.

Re-indexing is not automatic by default. It can be explicitly requested through `index_memory_scope(...)`, `auto_index=True` in the retrieval API, or the opt-in auto-index environment variable.

## Hybrid ranking

The lexical and semantic ranked lists are combined with RRF. Semantic matches are filtered by a minimum cosine-similarity threshold before fusion. The initial threshold is a conservative starting value (`0.2`) and should be calibrated with a reviewed bilingual retrieval dataset.

Retrieval is still bounded by per-category result limits. The knowledge graph remains a separate retrieval channel; graph traversal is not yet fused into the RRF ranking.

## Fail-safe behavior

- Feature disabled: lexical retrieval only.
- Missing model: lexical retrieval only.
- Missing vector index: lexical retrieval only unless auto-index is explicitly enabled.
- Embedding provider timeout or invalid response: lexical retrieval only.
- Stale vector: ignored.
- Dimension mismatch: ignored.
- Weak similarity: ignored.
- Scope mismatch: never queried or returned.

A provider outage must not make the base memory system unusable.

## Current limitations

- No built-in embedding model is bundled with Oracle.
- No actual Ollama or hosted embedding endpoint has been exercised by the offline CI.
- The included tests use deterministic fake embedding clients.
- Query and record embeddings are generated by the same configured model ID; changing model names requires a separate index.
- The initial similarity threshold is not a benchmark-derived optimum.
- Hybrid ranking currently fuses lexical and vector results; metadata, temporal, graph, and task-context reranking remain to be integrated.
- Memory revision history, valid-from/valid-until fields, importance/access statistics, supersession, and controlled consolidation remain unfinished Phase 02 requirements.
